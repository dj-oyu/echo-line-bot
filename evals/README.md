## 変更の意図

- あいちゃん、明るさ、親しみやすさ、自然な関西弁、相手の言語への対応は維持
- 関西の文化などへの親しみは維持し、相手の話題に沿って表現する位置づけに変更
- 定型の語尾を重ねる指示、毎回の時間帯挨拶、季節や文化の話題を自発的に提案する指示は整理
- 中心を「直近の発言の意図を受け止め、既知の条件と訂正を引き継ぐ」に変更
- 必要な確認と検索も、会話を進めるための同じ原則の中に置く
- 役割、モデル呼び出し回数、後段チェッカー、個別の禁止項目は追加しない

## 比較案

現行プロンプトと会話中心案を、同じ入力・共有履歴・モデル・設定で比較します。
7状況を各案2回ずつ、計28リクエストの小さな探索的比較を提案しています。
各状況はAB/BAを1回ずつにして実行順を揃えます。実行には別途判断が必要です。

1. 挨拶
2. 挨拶に続く仕事の近況
3. その会話から場所未指定の飲食店相談
4. 渋谷・2000円程度・和食という条件の共有
5. 「今そこの天気」という現在情報と参照先の解決
6. 渋谷から新宿への訂正と、未変更の予算・料理条件の継承
7. 訂正後に、以前の予算を思い出す質問

履歴は両案で同じ固定文を使います。前の出力の違いが次の入力条件に混ざらないように、
各チェックポイントの次の1応答を比較する設計です。自由に進行する一続きの会話や、
検索結果を模擬して最後まで返すテストではありません。実際の検索やLINE送信もしません。

将来の実行には検証済みの `dialect_diagnostic.sdk_call` を使えます。
OpenAI SDK 3.6.0、リトライ0、リダイレクトなし、1呼び出し1リクエストの制限を維持します。
モデルはgpt-oss-20b、reasoning medium、temperature 0.7、max_tokens 1000、tool_choice auto。
日時も固定し、ツール定義は現行と同じです。新しい実行経路はまだ追加していません。

見る点は、直近の意図への応答、条件や訂正の継承、確認質問、自然さ、検索判断とクエリです。
あわせて最初のモデル呼び出しの実測時間（各値・中央値・p95）、トークン数、返答の長さ、
打ち切り、モデル名とfingerprint、エラーを記録する想定です。API区間の時間は、LINE全体の
体感待ち時間とは別に扱います。今回は呼び出していないので品質・速度の改善結果はありません。

この案は指示の優先順位と話題の広げ方をまとめて変える比較です。個々の文だけの効果を
特定するものではなく、2回ずつの結果だけで安定性や統計的な優劣を断定しません。
